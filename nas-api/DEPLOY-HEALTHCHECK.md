# อัปสคริปต์ health check ขึ้น NAS (ทำครั้งเดียว ~2 นาที)

ทำไมต้องทำ · ตอนนี้ Task Scheduler ยิงไปที่ `diag.php` ซึ่งถูกถอดออกจาก webroot
ถาวรแล้ว (ตอบ 404 ทุกครั้ง) สคริปต์จึงเข้าใจว่าเว็บล่ม แล้ว **รีสตาร์ต Web Station
กับ Nginx ทิ้ง ๆ ขว้าง ๆ ทั้งที่ระบบปกติดี** · ทุกครั้งที่รีสตาร์ต การเชื่อมต่อที่ค้างอยู่
จะถูกตัดหมด รวมถึงการอัปโหลดรูป POD ที่กำลังทำงานอยู่

ไฟล์ใหม่แก้เรื่องนี้ให้ **โดยไม่ต้องแก้คำสั่งใน DSM** — แต่ถ้าแก้ด้วยจะสะอาดกว่า

---

## ไฟล์ที่ต้องอัป

| | |
|---|---|
| ต้นทาง | `nas-api/healthcheck-nas.sh` (ในโปรเจกต์นี้) |
| ปลายทาง | `/volume1/scripts/healthcheck-nas.sh` (ทับของเดิม) |
| ขนาด | 4,553 ไบต์ |
| MD5 | `6f12000bfe6cfa6d46491261ff9aa44e` |

> **สำคัญ:** ไฟล์ต้องเป็น **LF** เท่านั้น ห้ามเปิดแก้ด้วย Notepad แล้วเซฟ
> เพราะจะกลายเป็น CRLF แล้วบรรทัด `#!/bin/sh` จะกลายเป็น `#!/bin/sh\r`
> NAS จะฟ้อง `no such file or directory` ซึ่งอ่านไม่ออกว่าเกิดจากอะไร
> ถ้าลากไฟล์จากโปรเจกต์ไปตรง ๆ จะปลอดภัยเสมอ (git ตั้ง `.gitattributes` ไว้แล้ว)

---

## ขั้นตอน (File Station)

1. เปิด DSM → **File Station**
2. ไปที่โฟลเดอร์ `scripts`
3. ลากไฟล์ `nas-api/healthcheck-nas.sh` จากเครื่องเข้าไปวาง
4. เลือก **ทับไฟล์เดิม (Overwrite)**

เท่านี้พอ · สคริปต์ทำงานได้ทันทีในรอบถัดไปที่ Task Scheduler เรียก

---

## (ทางเลือก) แก้คำสั่งใน Task Scheduler ให้สะอาด

> **อัปเดต 27 ส.ค. 2569 15:4x** — ตรวจของจริงแล้วพบว่า **แก้ไปแล้วทั้งสองข้อ**
> คำสั่งปัจจุบันคือ `export ENDPOINT='...test.php'` (ไม่ใช่ diag.php แล้ว)
> และ Schedule เป็นทุกชั่วโมง 00:00–23:00 อยู่แล้ว
> **จึงไม่มีการรีสตาร์ตผิดพลาดเกิดขึ้นอีก** · ที่เหลือด้านล่างเป็นการทำความสะอาด
> ล้วน ๆ (ตัดบรรทัด export ทิ้ง) ไม่ใช่การแก้บั๊ก และไม่เร่งด่วน

DSM → **Control Panel → Task Scheduler** → งาน `NAS API Health Check` → Edit → Run command

เปลี่ยนจาก

```sh
ENDPOINT="https://neosiam.dscloud.biz/api/diag.php" sh /volume1/scripts/healthcheck-nas.sh
```

เป็น

```sh
sh /volume1/scripts/healthcheck-nas.sh
```

เหตุผล · ตัวแปรที่ใส่ไว้หน้าคำสั่ง **ชนะค่าเริ่มต้นในไฟล์เสมอ** ต่อให้อัปสคริปต์ใหม่
ขึ้นไปแล้ว คำสั่งเดิมก็ยังสั่งให้ยิงไป `diag.php` อยู่ดี · สคริปต์ใหม่ดักกรณีนี้ไว้แล้ว
(เปลี่ยนไป `test.php` ให้เอง แล้วเขียน log เตือน) แต่การแก้คำสั่งให้ตรงจะไม่ต้องพึ่งตัวดัก

ถ้าเข้าไปแก้แล้ว แนะนำตั้ง **Schedule เป็นทุกชั่วโมง** ด้วย (เดิมทุก 5 นาที)
เพราะ 5 นาทีถี่เกินความจำเป็นสำหรับงานที่ผลลัพธ์คือการรีสตาร์ตทั้งบริการ

---

## ตรวจว่าสำเร็จ

หลังอัปแล้ว รอรอบถัดไป แล้วดู log ที่สคริปต์เขียนไว้ (tag ชื่อ `nas-health`)

วิธีที่ง่ายที่สุดคือดูใน DSM → **Log Center** แล้วค้นคำว่า `nas-health`

ถ้าเข้า shell ได้ ลองไล่ตามนี้ (แล้วแต่รุ่น DSM ว่าเก็บไว้ที่ไหน):

```sh
grep nas-health /var/log/messages 2>/dev/null | tail -5
# ถ้าไม่มีไฟล์นั้น ลอง
logread 2>/dev/null | grep nas-health | tail -5
```

- **ไม่มีบรรทัดใหม่เลย** = ปกติดี ระบบสุขภาพดี ไม่มีการรีสตาร์ต ✅
- เจอ `ENDPOINT ... ถูกถอดออกจาก webroot แล้ว — ใช้ test.php แทน`
  = ตัวดักทำงาน (แปลว่ายังไม่ได้แก้คำสั่งใน Task Scheduler แต่ไม่รีสตาร์ตแล้ว) ✅
- เจอ `health check failed ... (ลอง 2 ครั้ง); restarting`
  = เว็บล่มจริง ตรวจ Web Station ต่อ

## สิ่งที่เปลี่ยนไปในสคริปต์

1. **ค่าเริ่มต้นชี้ไป `test.php`** (ไฟล์ถาวร 71 ไบต์ ตอบ 200 ไม่มีข้อมูลให้รั่ว)
2. **ดัก `diag.php` / `list-files.php` ที่ส่งมาจากคำสั่งเก่า** แล้วเปลี่ยนให้เอง
3. **ลองซ้ำ 2 ครั้ง ห่างกัน 5 วินาที ก่อนตัดสินว่าล่ม** — เน็ตกระตุกครั้งเดียว
   หรือ DNS ช้าชั่วขณะ ไม่ควรทำให้ทั้งระบบสะดุด

ทดสอบมาแล้วทั้ง 3 ทาง: คำสั่งเก่า / ค่าเริ่มต้น / เว็บล่มจริง
